**Objetivo:** pasar `archivo.sqlite` a v2 (viajes, visitas, lugares, aeropuertos, sellos, objetos sin evento, fotos sueltas) e importar `mis_viajes.xlsx`.

**Arquitectura:** todo sigue en `herramientas/archivo_db/archivo.py` (un comando por función `cmd_*`, como ahora). `schema.sql` pasa a ser el esquema v2 completo; `migraciones/002.sql` es el paso v1→v2. Los totales son vistas SQL.

**Tecnología:** Python 3 (stdlib `sqlite3`), `openpyxl` (ya instalado) para el Excel. Sin dependencias nuevas.

**Especificación:** `docs/superpowers/specs/2026-11-06-esquema-v2-design.md`

## Restricciones globales
- Español en mensajes, comentarios y docs.
- Toda importación es idempotente: repetir = `0 nuevos`.
- Nunca fusionar personas. No guardar datos sensibles.
- Pruebas siempre con `ARCHIVO_DB` y `ARCHIVO_FOTOS` temporales; nunca tocar `datos/archivo.sqlite` salvo en la Tarea 8.
- `PRAGMA user_version = 2`. Cambio de esquema = migración documentada.
- No hay git en el proyecto: los pasos de commit se sustituyen por `bash tests/run_all.sh` en verde. (Si Carla inicia git, usar `/commit` al final de cada tarea.)

## Puntos de revisión (casos que la especificación no prueba y que morderían)
1. Viaje del Excel sin fechas (Bruselas 2024) → se importa con `inicio`/`fin` NULL, sin error. Test en Tarea 4.
2. Visita cuyo nombre de viaje no está en la hoja Viajes → aviso con la fila, la visita se importa sin viaje. Test en Tarea 4.
3. Ciudad sin coordenadas en `ciudades_geo.csv` → lugar con lat/lng NULL y aviso. Test en Tarea 4.
4. `migrar` dos veces → la segunda dice "ya está en v2" y no hace nada. Test en Tarea 3.
5. Comandos v2 sobre una base v1 → error claro "ejecuta: archivo.py migrar". Test en Tarea 3.

### Tarea 3: esquema v2, migración y vistas

**Archivos:**
- Crear: `tests/fixtures/schema_v1.sql` (copia literal del `schema.sql` actual, antes de editarlo)
- Crear: `herramientas/archivo_db/migraciones/002.sql`
- Modificar: `herramientas/archivo_db/schema.sql` (v2 completo), `archivo.py` (`cmd_migrar`, `connect`)

**Esquema v2 (valores exactos):**
- `places(id, nombre NOT NULL, region, pais NOT NULL, continente, lat REAL, lng REAL, coord_confianza, UNIQUE(nombre, pais))`
- `airports(iata TEXT PRIMARY KEY CHECK(length(iata)=3), nombre, place_id → places, lat, lng)`
- `trips(id, slug UNIQUE NOT NULL, nombre NOT NULL, inicio, fin, transporte, salida, llegada, escala → airports(iata), motivo, notas)`; `inicio`/`fin` pueden ser NULL.
- `visits(id, place_id NOT NULL → places, trip_id → trips, inicio, fin, nota, UNIQUE(place_id, trip_id, inicio))`
- `events` + `place_id → places`, `trip_id → trips`; `photos` + `trip_id → trips`.
- `objects` reconstruida: `tipo IN ('lanyard','certificado','pin','sello','foto','otro')`; `event_id` NULL permitido; + `trip_id`, `place_id`, `fecha`, `sitio`, `titulo`, `organizador`; sin `pin_city`; `CHECK (event_id IS NOT NULL OR trip_id IS NOT NULL OR place_id IS NOT NULL OR titulo <> '')`.
- Vistas: `v_viajes(id, nombre, inicio, fin, dias = julianday(fin)-julianday(inicio)+1, anio = substr(inicio,1,4), estado = CASE WHEN inicio > date('now') THEN 'futuro' ELSE 'pasado' END)`, `v_paises(pais, continente, ciudades)`, `v_continentes(continente, paises, ciudades)`, `v_aeropuertos(iata, nombre, veces)` (cuenta salida+llegada+escala en `trips`).

**Migración `002.sql`:** procedimiento de SQLite para reconstruir `objects` (`PRAGMA foreign_keys=OFF`, crear `objects_new`, copiar, borrar, renombrar, índices, `foreign_key_check`). Los `pin_city` no vacíos crean su `places` (país vacío → `''`) y rellenan `place_id`.

**Interfaces:** Produce `version(con) -> int` y `exigir_v2(con)` (lanza `SystemExit("La base está en v1. Ejecuta: python archivo.py migrar")`). Todos los comandos nuevos llaman a `exigir_v2`.
